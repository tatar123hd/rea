## 5.4 ตรวจ delegation ทุก query ที่ยิงไป SharePoint

| ที่ | สูตร (ย่อ) | เงื่อนไขที่ใช้ | delegate ได้ |
|---|---|---|---|
| LoadData B | `Filter(Projects, Department=, StartDate<=, EndDate>=)` | `=` text indexed, `<=`/`>=` date indexed | ✔ |
| LoadData B | `Filter(Phases, Department=, StartDate<=, EndDate>=)` | เหมือนกัน | ✔ |
| LoadData B | `Filter(Tasks, Department=, StartDate<=, DueDate>=)` | เหมือนกัน | ✔ |
| LoadData B | `SortByColumns(ShowColumns(Projects,...), "Title")` | sort บน text | ✔ |
| LoadData C | `Filter(BAU_TMP, StartDate<=, EndDate>=)` | `<=`/`>=` date | ✔ (ต้อง index ที่ฝั่ง BAU ด้วย) |
| OnStart | `LookUp(AppAdmins, Email = ...)` | `=` text indexed | ✔ |
| OpenDetail | `LookUp(<list>, ID = n)` | `=` บน ID | ✔ |
| scrTable | `Filter(Tasks, Department=, ID>, StartsWith(Title,...), StatusKey=)` + `SortByColumns("ID")` + `FirstN` | ทั้งหมด delegate ได้บน SharePoint | ✔ |
| scrSkills | `Filter(SkillsInterests, Department=, StartsWith(Title,...))` | `=` + StartsWith | ✔ |
| scrMyTasks | `Filter(Tasks, AssignedToEmail=, StatusKey<>)` | `=` และ `<>` text indexed | ✔ |
| scrMyTasks | `Filter(BAU_TMP, EndDate>=, StartDate<=)` | date | ✔ |
| scrProject | `Filter(Phases, ProjectID = n)` / `Filter(Tasks, PhaseID = n)` | `=` number indexed | ✔ |
| scrProject | `Filter(TaskTemplates, PhaseType = ...)` | `=` text indexed | ✔ |
| scrProject | `First(SortByColumns(Filter(Phases, ProjectID=n), "StartDate"))` | filter + sort บน indexed | ✔ |
| scrAdmin | `ForAll(Projects ...)` ซ้อน `Filter(Phases, ProjectID=)` | delegate ได้ แต่ดึงได้ครั้งละไม่เกินเพดานแถว | ⚠️ ดู §5.7 L3 |

**ไม่มีการใช้** `Search()`, `in` กับ data source, `CountRows(Filter(<list>,…))`, หรือ `LookUp` ซ้อนใน gallery items ที่ชี้ไป data source

## 5.5 คำเตือน delegation ที่ "ยอมรับได้" (ไม่ต้องแก้)

Studio จะขึ้นสามเหลี่ยมสีน้ำเงินในกรณีเหล่านี้ ซึ่ง **ไม่ใช่ปัญหา** เพราะทำงานบน collection

- ทุกสูตรที่ขึ้นต้นด้วย `Filter(colTasksF, …)`, `Filter(colBauF, …)`, `Filter(colTimelineAll, …)`
- `CountRows(colTasksF)` และตัวนับทั้งหมดบนหน้า Dashboard
- `GroupBy` / `AddColumns` ในกราฟปริมาณงาน
- `Distinct(colBau, CourseArea)` และตัวเลือกตัวกรอง BAU
- `Filter(Office365Users.SearchUserV2(...).value, …)` — เป็น API ไม่ใช่ตาราง SharePoint

**คำเตือนบนชื่อ data source จริง (`Projects` `Phases` `Tasks` `BAU_TMP` `SkillsInterests` `AppAdmins` `TaskTemplates`) ต้องแก้เสมอ** ถ้าเจอ แปลว่ามีสูตรที่หลุดจากแบบ

## 5.6 ปัญหาที่พบระหว่างตรวจเอกสารชุดนี้ และแก้แล้ว

| # | ปัญหา | แก้อย่างไร |
|---|---|---|
| F1 | ในปฏิทิน `ThisItem.Day` ถูกอ้างภายใน `Filter()` ซึ่ง row scope อาจบังชื่อ ทำให้ความหมายกำกวม | ห่อด้วย `With({dd: ThisItem.Day}, …)` และตั้ง alias ให้ทุก `Filter` (`As b0`, `As t0`) |

| L5 | ชุดคำสั่ง LoadData ถูกวาง 2 ที่ | ต้องแก้ทั้งสองที่พร้อมกันเสมอ | ถ้า environment เปิด user-defined function แบบมีผลข้างเคียง ให้ย้ายไป App.Formulas เหลือสำเนาเดียว |
| L6 | ตัวกรองแผนกของ BAU พึ่ง Office 365 Users | ถ้าโปรไฟล์ไม่มีแผนก รายการนั้นจะไม่ตรงกับตัวกรองแผนกใด ๆ | ใช้ **ทุกแผนก** หรือขอให้เจ้าของลิสต์เพิ่มคอลัมน์ Department (ตอนนี้ห้ามแก้ BAU) |
| L7 | เจ้าของที่ถูกโอนสิทธิ์ผ่านหน้าผู้ดูแล จะแก้ผ่านหน้าลิสต์ SharePoint โดยตรงไม่ได้ | แก้ผ่านแอปได้ปกติ | ให้ site owner แก้ค่า Author ด้วย PnP |

## 5.8 แผนทดสอบ

### ข้อมูลตัวอย่างที่ต้องเตรียม

| ชุด | รายละเอียด |
|---|---|
| D1 | 3 โปรเจกต์ที่ช่วงเวลาทับกัน แต่ละโปรเจกต์มี 3–5 เฟส เฟสละ 3 งาน (สคริปต์ PnP สร้างให้แล้ว) |
| D2 | งาน 1 รายการที่กำหนดส่งผ่านไปแล้วและสถานะยังไม่ใช่ "เสร็จแล้ว" (สคริปต์สร้างให้แล้ว) |
| D3 | โปรเจกต์ 1 รายการที่สร้างโดยผู้ใช้คนอื่น (ให้เพื่อนร่วมงานสร้างให้ 1 อัน) |
| D4 | ลิสต์ Tasks ที่มีมากกว่า 2,000 แถว (วิธีสร้างอยู่ใน T-13) |
| D5 | รอบอบรม BAU ที่สถานะ `ยกเลิก` และ `รอยืนยัน` อย่างละอย่างน้อย 1 รายการ |
| D6 | ผู้ใช้ทดสอบ 4 คน: เจ้าของโปรเจกต์ / ผู้ดูที่ไม่ใช่เจ้าของ / ผู้ดูแลระบบ / ผู้ใช้ที่ไม่มีสิทธิ์ BAU |
| D7 | ผู้ใช้ 1 คนที่โปรไฟล์ Microsoft 365 ไม่มีค่า Department |

### ตารางทดสอบ

| รหัส | บทบาท | สิ่งที่ทำ | ผลที่คาดหวัง |
|---|---|---|---|
| **T-01** | ทุกคน | เปิดแอปครั้งแรก | ตัวกรองแผนก = แผนกของผู้ใช้, ช่วงเวลา = เดือนปัจจุบัน, ไทม์ไลน์แสดงข้อมูล, ไม่มีข้อความแดง |
| **T-02** | ทุกคน | กด **รีเฟรชข้อมูล** บนหัวหน้าจอ | ข้อมูลโหลดใหม่ ขึ้นข้อความเขียว "โหลดข้อมูลใหม่เรียบร้อยแล้ว" (ถ้าไม่ทำงาน = ข้อ U9 ให้ย้ายปุ่มออกจากคอมโพเนนต์) |
| **T-03** | ทุกคน | เลือกโปรเจกต์ 2 อันในช่องโปรเจกต์ → **ใช้ตัวกรอง** | เห็นเฉพาะ 2 โปรเจกต์นั้นกับเฟส/งานของมัน |
| **T-04** | ทุกคน | สลับไป **ภาพรวม** → **กระดานงาน** → กลับ **ไทม์ไลน์** | ตัวกรองทุกช่องยังเป็นค่าเดิมทุกครั้ง |
| **T-05** | ทุกคน | กดลูกศรย่อหน้าชื่อโปรเจกต์ | เฟสและงานของโปรเจกต์นั้นหายไป แถวอื่นไม่กระทบ กดอีกครั้งกลับมา |
| **T-06** | ทุกคน | เปลี่ยนซูมเป็น **รายสัปดาห์** แล้ว **รายไตรมาส** | ไม้บรรทัดเปลี่ยนความถี่ แถบยืด/หดตามสัดส่วน เส้น "วันนี้" ยังตรงตำแหน่ง |
| **T-07** | ทุกคน | ดูงานในชุด D2 | แถบมีขอบแดง + ไอคอนเตือน และวันกำหนดส่งเป็นสีแดงในหน้าตาราง/กระดาน |
| **T-08** | เจ้าของโปรเจกต์ | สร้างโปรเจกต์ใหม่ → เพิ่ม 2 เฟส | ช่วงเวลาโปรเจกต์ = วันเริ่มของเฟสแรก ถึง วันจบของเฟสท้ายสุด โดยอัตโนมัติ |
| **T-09** | เจ้าของโปรเจกต์ | ลบเฟสกลางทิ้ง | กล่องยืนยันบอกจำนวนงานที่จะถูกลบ หลังยืนยัน งานในเฟสหายไปด้วย และช่วงเวลาโปรเจกต์คำนวณใหม่ |
| **T-10** | เจ้าของโปรเจกต์ | เลือกเฟสแล้วติ๊กงานแนะนำ 3 อัน → **เพิ่มงานที่เลือก** | ได้งาน 3 รายการ ผู้รับผิดชอบและวันที่รับมาจากเฟส |
| **T-11** | ผู้ดูที่ไม่ใช่เจ้าของ | เปิดโปรเจกต์ D3 แล้วกดที่แถบ | ปุ่ม **แก้ไข** และ **ลบ** เป็นสีเทา มีข้อความ "คุณดูได้อย่างเดียว…" |
| **T-11b** | ผู้ดูที่ไม่ใช่เจ้าของ | เปิดลิสต์ `Tasks` ใน SharePoint ตรง ๆ แล้วลองแก้แถวของคนอื่น | SharePoint ปฏิเสธ (พิสูจน์ว่าการคุมสิทธิ์ไม่ได้อยู่แค่ในแอป) |
| **T-12** | ทุกคน | บันทึกเฟสที่วันเริ่ม = **1 ม.ค.** แล้วเปิดลิสต์ใน SharePoint | ค่าในลิสต์เป็น 1 ม.ค. ไม่ใช่ 31 ธ.ค. และแอปแสดง `1 Jan <ปี ค.ศ.>` |
| **T-13** | ผู้ดูแลระบบ | สร้างงานให้เกิน 2,000 แถว (ใช้ PnP วนลูป `Add-PnPListItem` 2,500 ครั้ง) แล้วเปิดหน้า **ตาราง** | เลื่อนหน้าได้เกินหน้า 40 โดยไม่มีคำเตือน และไม่มีแถวซ้ำ/ตกหล่นที่รอยต่อหน้า |
| **T-13b** | ผู้ดูแลระบบ | จากข้อมูลเดียวกัน เปิด **ไทม์ไลน์** แล้วเลือก **รายไตรมาส** + **ทุกแผนก** | ถ้าชนเพดาน ต้องขึ้นแถบส้ม "ข้อมูลถูกตัด…" ไม่ใช่แสดงข้อมูลไม่ครบเงียบ ๆ |
| **T-14** | ทุกคน | ดูรอบอบรมชุด D5 | รายการ `ยกเลิก` ไม่แสดง จนกว่าจะเปิดสวิตช์; รายการ `รอยืนยัน` แสดงเป็นเส้นประสีอ่อน |

| **T-19b** | ผู้ใช้ทั่วไป | เปิดหน้าทักษะ | ไม่เห็นปุ่มเพิ่ม/แก้/ลบ แม้แต่ของตัวเอง |

- [ ] **T-13** และ **T-13b** — พฤติกรรมเมื่อข้อมูลเกิน 2,000 แถว

- [ ] **T-15** — ผู้ใช้ที่ไม่มีแผนกยังใช้แอปได้
