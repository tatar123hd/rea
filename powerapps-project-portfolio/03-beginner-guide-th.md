# ส่วนที่ 3 — คู่มือสร้างแอปสำหรับมือใหม่ (ตั้งแต่ศูนย์)

อ่านไล่จากข้อ 1 ถึงข้อสุดท้าย ไม่ต้องข้าม ใช้เวลาประมาณ 3–5 ชั่วโมงถ้าทำครั้งแรก

> **ชื่อปุ่มและเมนู** ในคู่มือนี้เขียนตามที่ปรากฏจริงใน Power Apps Studio และ SharePoint
> ซึ่ง Microsoft **เปลี่ยนชื่อเมนูอยู่เรื่อย ๆ** ถ้าหาปุ่มตามที่เขียนไม่เจอ ให้มองหาคำที่ใกล้เคียง
> หรือใช้ช่องค้นหาด้านบนของ Studio แล้วพิมพ์ชื่อคำสั่ง ทุกครั้งที่คู่มือเตือนเรื่องนี้จะมีเครื่องหมาย ⚠️

## ตอนที่ 1 — เตรียมข้อมูลใน SharePoint

### 1.1 เปิด SharePoint

1. เปิดเบราว์เซอร์ ไปที่ `https://www.office.com`
2. ลงชื่อเข้าใช้ด้วยบัญชีที่ทำงาน
3. กดไอคอนตารางเก้าจุดมุมซ้ายบน (**App launcher**) → เลือก **SharePoint**

### 1.2 สร้าง site สำหรับเก็บข้อมูล (ถ้ายังไม่มี)

1. กด **+ Create site**
2. เลือก **Team site**
3. ตั้งชื่อ เช่น `Project Portfolio` → **Next** → **Finish**
4. **คัดลอก URL ของ site เก็บไว้** จะใช้ตอนเชื่อมต่อ

### 1.3 สร้างลิสต์ทั้ง 6 ลิสต์

ทำตามไฟล์ **`02-sharepoint-setup.md`** เลือกทางใดทางหนึ่ง

- ถ้าถนัด PowerShell → รันสคริปต์ `sharepoint/Provision-ProjectPortfolio.ps1` (เร็วที่สุด ได้ข้อมูลตัวอย่างครบ)
- ถ้าไม่ถนัด → ทำมือตามหัวข้อ 2.3 ในไฟล์นั้น

**ก่อนไปต่อ ตรวจให้ครบ**

- [ ] มีลิสต์ `Projects` `Phases` `Tasks` `TaskTemplates` `SkillsInterests` `AppAdmins`
- [ ] คอลัมน์ที่ต้อง index ถูก index แล้ว
- [ ] `TaskTemplates` มีข้อมูลงานแนะนำแล้ว
- [ ] Time zone ของ site คือ **(UTC+07:00) Bangkok**
- [ ] ตัวเองอยู่ในลิสต์ `AppAdmins` และอยู่ในกลุ่ม `PP_Admins`

### 1.4 ตรวจสิทธิ์อ่านลิสต์ BAU

1. เปิด URL ของลิสต์ BAU (L&D TMP) ในเบราว์เซอร์
2. ถ้าเห็นข้อมูล = มีสิทธิ์อ่านแล้ว ผ่าน
3. ถ้าขึ้นว่าไม่มีสิทธิ์ ให้ขอสิทธิ์ **Read** จากเจ้าของลิสต์ก่อน (อย่าแก้สิทธิ์เอง)
4. จด **ชื่อลิสต์ BAU** ไว้ และตรวจชนิดคอลัมน์ `Responder` `LM` `Status` ตามไฟล์ `01` หัวข้อ 1.3

## ตอนที่ 2 — สร้างแอปเปล่า

### 2.1 เปิด Power Apps

1. ไปที่ `https://make.powerapps.com`
2. มุมขวาบน ตรวจว่า **Environment** ถูกต้อง (ถ้ามีหลายอัน ให้ถามผู้ดูแล)

### 2.2 สร้างแอป

1. เมนูซ้าย กด **+ Create**
2. เลือก **Blank app**
3. เลือก **Blank canvas app** → กด **Create**
4. **App name** ใส่ `Project Portfolio`
5. **Format** เลือก **Tablet** (ได้ขนาด 16:9 เหมาะกับเดสก์ท็อป)
6. กด **Create**

⚠️ บางเวอร์ชันหน้านี้ชื่อ **Start from blank** หรือมีให้เลือก Format ตอนหลัง
ถ้าเลือก Phone ไปแล้ว ให้ไปแก้ที่ **Settings → Display → Orientation = Landscape**

### 2.3 ตั้งค่าแอป

1. มุมซ้ายบน กด **Settings** (ไอคอนฟันเฟือง)
2. **Display**
   - **Orientation** = **Landscape**
   - **Aspect ratio** = **16:9**
   - **Scale to fit** = **Off** (ปิด เพื่อให้ขนาดคงที่ 1366×768)
   - **Lock aspect ratio** = **On**
3. **General** (หรือ **Updates → Data**)
   - **Data row limit** ตั้งเป็น **2000**
     ⚠️ แอปนี้ **ไม่ได้พึ่งค่านี้เพื่อความถูกต้อง** ทุก query ถูกออกแบบให้ delegate ได้อยู่แล้ว
     ค่านี้มีไว้กันกรณีช่วงเวลากว้างผิดปกติ และแอปจะขึ้นแถบเตือนให้ลดช่วงเวลาเอง
4. **Upcoming features** → ค้นคำว่า `named formulas`
   ตรวจว่า **Enhanced component properties** และ **named formulas** เปิดอยู่
   ⚠️ ชื่อสวิตช์เปลี่ยนบ่อยมาก ถ้าไม่เจอ ให้ลองไปต่อ แล้วถ้าวาง App.Formulas ไม่ได้ค่อยกลับมาหา

## ตอนที่ 3 — เชื่อมต่อข้อมูล

ทำทีละลิสต์ รวม 7 แหล่ง (6 ลิสต์ใหม่ + 1 ลิสต์ BAU) และ 1 connector

### 3.1 เพิ่มลิสต์ใหม่

1. เมนูซ้ายใน Studio กด **Data** (ไอคอนรูปถังข้อมูล)
2. กด **+ Add data**
3. พิมพ์ `SharePoint` แล้วเลือก **SharePoint**
4. เลือก connection ที่มีอยู่ หรือกด **+ Add a connection** → **Connect** → ลงชื่อเข้าใช้
5. ช่อง **Enter a SharePoint site URL** ใส่ URL ของ site แล้วกด **Connect**
6. ติ๊กทั้ง 6 ลิสต์: `AppAdmins` `Phases` `Projects` `SkillsInterests` `TaskTemplates` `Tasks`
7. กด **Connect**

### 3.2 เพิ่มลิสต์ BAU

1. กด **+ Add data** → **SharePoint** อีกครั้ง
2. ใส่ URL ของ site ที่เก็บลิสต์ BAU (คนละ site ก็ได้)
3. ติ๊กลิสต์ BAU → **Connect**
4. ดูชื่อที่ปรากฏในรายการ **Data** ทางซ้าย — **นี่คือชื่อที่ต้องใช้ในสูตร**
5. ถ้าชื่อไม่ใช่ `BAU_TMP` ให้จำไว้ แล้วตอนวางสูตรให้แทนที่คำว่า `BAU_TMP` ด้วยชื่อจริงทุกจุด

⚠️ Power Apps **ไม่รองรับการตั้งชื่อเล่น (alias)** ให้ data source ชื่อจึงถูกเขียนตรง ๆ ในสูตร
วิธีที่เร็วที่สุดคือเปิดไฟล์ YAML/สูตรใน Notepad แล้วใช้ **Replace All**

### 3.3 เพิ่ม Office 365 Users

1. กด **+ Add data**
2. พิมพ์ `Office 365 Users` แล้วเลือก
3. กด **Connect**

**ตรวจก่อนไปต่อ:** ในแผง Data ต้องมี 8 รายการ (6 ลิสต์ใหม่ + ลิสต์ BAU + Office365Users)

## ตอนที่ 4 — วางธีมและสูตรเริ่มต้น

### 4.1 App.Formulas

1. ใน **Tree view** (เมนูซ้าย) คลิกที่คำว่า **App** บนสุด
2. ที่แถบสูตรด้านบน มีช่องเลือกคุณสมบัติ (ปกติขึ้นว่า `OnStart`) กดแล้วเลือก **Formulas**
3. เปิดไฟล์ `powerapps/App.Formulas.pafx.txt` → เลือกทั้งหมด (Ctrl+A) → คัดลอก (Ctrl+C)
4. กลับมาวางในช่องสูตร (Ctrl+V)
5. ตรวจว่าไม่มีขีดแดง ถ้ามีให้ดูหัวข้อ "แก้ปัญหา" ท้ายคู่มือ

### 4.2 App.OnStart

1. ยังอยู่ที่ **App** เปลี่ยนช่องคุณสมบัติเป็น **OnStart**
2. วางเนื้อหาไฟล์ `powerapps/App.OnStart.pafx.txt`
3. **สำคัญ** ไปที่บรรทัดสุดท้ายที่เขียนว่า *"วางเนื้อหาทั้งหมดของ shared/LoadData.pafx.txt ต่อจากบรรทัดนี้"*
   แล้ววางเนื้อหาไฟล์ `powerapps/shared/LoadData.pafx.txt` ต่อท้าย
4. ในไฟล์ LoadData มองหาคำว่า `<<< ชุด PERSON >>>` และ `<<< ชุด TEXT >>>`
   **เก็บไว้ชุดเดียวตามชนิดคอลัมน์จริง** แล้วลบ/คอมเมนต์อีกชุดทิ้ง

## ตอนที่ 5 — สร้างคอมโพเนนต์

ทำ 6 ตัว: `cmpSidebar` `cmpHeader` `cmpFilters` `cmpConfirm` `cmpDetailPanel` `cmpTimelineBar`

สำหรับแต่ละตัว ทำแบบนี้

1. ใน **Tree view** กดแท็บ **Components** (อยู่ข้างแท็บ Screens)
2. กด **+ New component**
3. คลิกชื่อที่ได้ (เช่น `Component1`) → กด **Rename** → ใส่ชื่อตามไฟล์ เช่น `cmpSidebar`
4. ที่แผงคุณสมบัติด้านขวา ตั้ง **Width** และ **Height** ตามที่เขียนไว้หัวไฟล์ YAML
5. ถ้าหัวไฟล์เขียนว่า *ต้องเปิด Access app scope* ให้เลื่อนหาสวิตช์ **Access app scope** แล้วเปิด
6. สร้าง **custom properties** ตามตารางหัวไฟล์
   - กด **+ New custom property**
   - **Display name** และ **Name** ใส่ตามตาราง
   - **Property type** เลือกตามตาราง (Input / Output / Behavior)
   - **Data type** เลือกตามตาราง
   - กด **Create**
   - ทำซ้ำจนครบทุกบรรทัดในตาราง
7. วางคอนโทรลข้างใน: เปิดไฟล์ YAML ของคอมโพเนนต์นั้น คัดลอกเฉพาะส่วนใต้ `Children:`
   แล้วคลิกบนพื้นที่ว่างของคอมโพเนนต์ กด **Ctrl+V**

⚠️ ถ้าวาง YAML ไม่ได้ (ขึ้นว่าไม่รู้จักชนิดคอนโทรล) ให้อ่าน `powerapps/components/README-components.md`
มีวิธีหาชื่อชนิดคอนโทรลที่ถูกต้องของเวอร์ชันคุณ

## ตอนที่ 6 — สร้างหน้าจอ

สร้าง 10 หน้าจอ ตามชื่อนี้ **สะกดให้ตรงเป๊ะ** เพราะสูตรนำทางอ้างชื่อเหล่านี้

`scrTimeline` `scrDashboard` `scrBoard` `scrTable` `scrCalendar` `scrMyTasks`
`scrSkills` `scrHelp` `scrAdmin` `scrProject`

สำหรับแต่ละหน้าจอ

1. แท็บ **Screens** → กด **+ New screen** → เลือก **Blank**
2. คลิกชื่อหน้าจอ → **Rename** → ใส่ชื่อตามรายการ
3. เลือกหน้าจอ แล้วตั้ง **Fill** = `clrBg`
4. เปิดไฟล์ YAML ของหน้าจอนั้นใน `powerapps/screens/`
5. คัดลอกเฉพาะส่วนใต้ `Children:` แล้วคลิกบนพื้นที่ว่างของหน้าจอ กด **Ctrl+V**
6. ตั้งคุณสมบัติ **OnVisible** ของหน้าจอตามที่เขียนไว้ในส่วน `Properties:` ของไฟล์

### 6.1 จุดที่ต้องวางสูตรเพิ่มด้วยมือ

มี 3 จุดที่ YAML เขียนไว้เป็นคอมเมนต์ เพราะสูตรยาวเกินกว่าจะใส่ซ้ำได้

| ที่ | ต้องวางอะไร |
|---|---|
| `cmpFilters` → `btnApply` → **OnSelect** ตรงบรรทัด `// << วางเนื้อหาทั้งหมดของ shared/LoadData.pafx.txt ตรงนี้ >>` | เนื้อหาไฟล์ `shared/LoadData.pafx.txt` |
| `scrTimeline` → `galTimeline` → `cmpTimelineBar_1` → **OnSelectBar** | เนื้อหาไฟล์ `shared/OpenDetail.pafx.txt` |
| App.OnStart ท้ายไฟล์ | เนื้อหาไฟล์ `shared/LoadData.pafx.txt` (ชุดเดียวกับข้างบน) |

> ⚠️ **ต้องเป็นข้อความเดียวกันเป๊ะทั้งสองที่** ถ้าแก้ที่หนึ่งต้องแก้อีกที่ด้วยเสมอ
> นี่เป็นข้อจำกัดของ Power Apps ที่ยังไม่มีฟังก์ชันผู้ใช้สร้างเองแบบมีผลข้างเคียงที่ใช้ได้ทุก environment

### 6.2 ตั้งหน้าจอแรก

1. ใน Tree view คลิกขวาที่ `scrTimeline`
2. เลือก **Move up** จนขึ้นไปอยู่บนสุด (หน้าจอบนสุดคือหน้าแรกที่เปิด)

## ตอนที่ 7 — ทดสอบในเครื่อง

1. กด **F5** หรือปุ่มสามเหลี่ยม **Preview** มุมขวาบน
2. ถ้ามีหน้าต่างขออนุญาตการเชื่อมต่อ กด **Allow**
3. ตรวจตามรายการนี้

- [ ] เห็นไทม์ไลน์มีแถบสี
- [ ] เส้นสีแดง "วันนี้" อยู่ตำแหน่งที่ถูกต้อง
- [ ] กดลูกศรย่อ/ขยายได้
- [ ] กดแถบแล้วแผงรายละเอียดเปิดทางขวา
- [ ] เปลี่ยนช่วงเวลาแล้วกด **ใช้ตัวกรอง** ข้อมูลเปลี่ยนตาม
- [ ] สลับไปหน้าอื่นแล้วกลับมา ตัวกรองยังอยู่เหมือนเดิม
- [ ] กด **สร้างโปรเจกต์ใหม่** บันทึกได้ เพิ่มเฟสได้ เพิ่มงานจากงานแนะนำได้
- [ ] เมนู **ผู้ดูแลระบบ** แสดงเฉพาะเมื่อคุณอยู่ในลิสต์ AppAdmins

4. กด **Esc** เพื่อออกจากโหมดทดสอบ

### 7.1 ตรวจคำเตือน delegation

1. ในแถบเครื่องมือด้านบน กด **App checker** (ไอคอนเครื่องหมายถูกในวงกลม)
2. ดูหัวข้อ **Formulas** หรือ **Delegation**
3. ถ้ามีคำเตือนรูปสามเหลี่ยมสีน้ำเงิน ให้เทียบกับตาราง "คำเตือนที่ยอมรับได้" ในไฟล์ `05`
   คำเตือนที่ไม่ได้อยู่ในตารางนั้น **ต้องแก้**

## ตอนที่ 8 — บันทึกและแชร์แอปให้เพื่อนร่วมงาน

### 8.1 บันทึกและเผยแพร่

1. มุมขวาบน กด **Save**
2. รอจนขึ้นว่า **Saved**
3. กด **Publish** → **Publish this version**

⚠️ ถ้าไม่กด Publish เพื่อนร่วมงานจะยังเห็นเวอร์ชันเก่า การกด Save อย่างเดียวไม่พอ

### 8.2 แชร์แอป

1. กลับไปที่ `https://make.powerapps.com` → เมนูซ้าย **Apps**
2. หาแอป `Project Portfolio` → กดจุดสามจุด (**…**) → **Share**
3. ช่องค้นหา ใส่ชื่อคน หรือชื่อกลุ่ม Microsoft 365 (แนะนำให้ใช้กลุ่ม จัดการง่ายกว่า)
4. เลือกระดับสิทธิ์ **Can use**
   (เลือก **Co-owner** เฉพาะคนที่ต้องแก้ไขตัวแอปจริง ๆ)
5. ตรวจส่วน **Data permissions** ด้านล่าง — จะมีข้อความว่าผู้ใช้ต้องมีสิทธิ์บน SharePoint ด้วย
6. ติ๊ก **Send an email invitation to new users** ถ้าต้องการให้ระบบส่งลิงก์ให้
7. กด **Share**

### 8.3 ให้สิทธิ์ SharePoint แก่ผู้ใช้

การแชร์แอป **ไม่ได้** ให้สิทธิ์ข้อมูลโดยอัตโนมัติ ต้องทำเพิ่ม

1. เปิด SharePoint site → **Settings** → **Site permissions**
2. กด **Invite people** → **Share site only**
3. ใส่ชื่อกลุ่มหรือรายชื่อ → เลือก **Edit** (เพื่อให้สร้างโปรเจกต์ของตัวเองได้)
4. กด **Add**

> สิทธิ์ระดับรายการที่ตั้งไว้ (แก้ได้เฉพาะของตัวเอง) ยังทำงานอยู่ ผู้ใช้จึงแก้ของคนอื่นไม่ได้
> แม้จะได้สิทธิ์ **Edit** ที่ระดับ site

5. สำหรับลิสต์ BAU: ให้เจ้าของลิสต์นั้นให้สิทธิ์ **Read** แก่ผู้ใช้กลุ่มเดียวกัน

### 8.4 ส่งข้อความแจ้งผู้ใช้ (คัดลอกไปใช้ได้เลย)

## ตอนที่ 9 — แก้ปัญหาที่พบบ่อย

### 9.1 คำเตือน delegation (สามเหลี่ยมสีน้ำเงิน)

**ข้อความ:** *"Delegation warning. The highlighted part of this formula might not work correctly on large data sets."*

| สาเหตุ | วิธีแก้ |
|---|---|
| ใช้ `Search()` | เปลี่ยนเป็น `StartsWith()` |
| ใช้ `in` กับ collection บน data source | ดึงข้อมูลตามช่วงวันที่ก่อน แล้วกรองบน collection |
| กรองด้วย `AssignedTo.Email` (Person) | ใช้คอลัมน์ `AssignedToEmail` แทน |
| `CountRows(Filter(Tasks, ...))` | นับบน collection ที่โหลดมาแล้ว |
| เตือนบนบรรทัดที่ขึ้นต้นว่า `Filter(colXxx, ...)` | **ไม่ต้องแก้** นี่คือ collection ในเครื่อง ไม่ใช่ SharePoint |

### 9.2 เชื่อมต่อ connector ไม่ได้ / ถูกถาม sign-in ซ้ำ

1. **Data** → หา connection ที่มีสัญลักษณ์ตกใจ → กดจุดสามจุด → **Refresh**
2. ถ้ายังไม่ได้ ไปที่ make.powerapps.com → **Connections** → ลบ connection เดิม → สร้างใหม่
3. ถ้าองค์กรบังคับ MFA อาจต้องลงชื่อใหม่ทุก ๆ 90 วัน ถือเป็นเรื่องปกติ

### 9.3 ขึ้นว่าไม่มีสิทธิ์บนลิสต์ BAU

**อาการ:** แถบเตือนสีเหลือง *"ไม่สามารถอ่านข้อมูล BAU ได้"*

1. ให้ผู้ใช้เปิด URL ลิสต์ BAU ตรง ๆ ในเบราว์เซอร์ ถ้าเปิดไม่ได้ = ไม่มีสิทธิ์จริง
2. ขอสิทธิ์ **Read** จากเจ้าของลิสต์ **ห้ามแก้สิทธิ์เอง** เพราะอาจกระทบแอป L&D TMP
3. ถ้าเปิดได้แต่แอปยังเตือน ให้ตรวจชื่อ data source ในสูตรว่าตรงกับชื่อจริงหรือยัง

### 9.4 ข้อมูล BAU ไม่ขึ้นเลยทั้งที่มีสิทธิ์

เรียงลำดับตรวจดังนี้

1. ติ๊ก **อบรม BAU** ในแถบตัวกรองแล้วหรือยัง
2. ช่วงวันที่ที่เลือกมีรอบอบรมหรือไม่ ลองเปลี่ยนเป็น **รายไตรมาส**
3. ตัวกรองแผนกตั้งเป็นแผนกที่ไม่มีคนรับผิดชอบรอบอบรมหรือเปล่า ลองเลือก **ทุกแผนก**
4. รายการที่ **ยกเลิก** ถูกซ่อนไว้ ลองเปิดสวิตช์ **แสดงรายการยกเลิก**
5. ชื่อคอลัมน์ในสูตรตรงกับลิสต์จริงหรือไม่ (`StartDate` `EndDate` `CourseArea` `LearningType` `Status`)
6. ชนิดคอลัมน์ Responder/LM ตรงกับชุดสูตรที่เลือกใช้หรือไม่ (Person vs Text)

### 9.5 ค่าแผนกว่าง

**อาการ:** แถบเตือน *"โปรไฟล์ของคุณไม่มีข้อมูลแผนก"*

- เกิดจาก Microsoft 365 ไม่ได้กรอกช่อง **Department** ให้ผู้ใช้คนนั้น
- แอปจะตั้งตัวกรองเป็น **ทุกแผนก** ให้อัตโนมัติ ใช้งานต่อได้
- แก้ถาวร: ฝ่ายไอทีไปที่ Microsoft 365 admin center → **Users** → **Active users**
  → เลือกคน → **Manage contact information** → กรอก **Department** → **Save**
- หลังแก้ ค่าจะใช้เวลาสักพักกว่าจะอัปเดต ให้ปิดแอปแล้วเปิดใหม่

### 9.6 วันที่คลาดเคลื่อนไป 1 วัน

1. ตรวจ time zone ของ SharePoint site = **(UTC+07:00) Bangkok**
2. ตรวจว่าคอลัมน์วันที่เป็น **Date Only** ไม่ใช่ Date and Time
3. ตรวจว่าสูตรบันทึกใช้ `DateAdd(<วันที่>, 12, TimeUnit.Hours)` ครบทุกจุด
4. ตรวจว่าสูตรแสดงผลมี `"en-US"` ต่อท้าย: `Text(d, "d mmm yyyy", "en-US")`

### 9.7 วาง YAML ไม่ได้

- ดูไฟล์ `powerapps/components/README-components.md`
- วิธีที่ชัวร์ที่สุด: สร้างคอนโทรลชนิดนั้น 1 ตัวด้วยมือ กด Ctrl+C วางใน Notepad
  แล้วดูว่าบรรทัด `Control:` เขียนว่าอะไร จากนั้นแก้ไฟล์ให้ตรง

### 9.8 บันทึกแล้วขึ้นข้อความสีแดง

| ข้อความที่เห็น | ความหมาย | วิธีแก้ |
|---|---|---|
| ...*does not have permission*... | ไม่ใช่ผู้สร้างรายการนั้น | ให้ผู้สร้างแก้ หรือใช้หน้าผู้ดูแลโอนความเป็นเจ้าของ |
| ...*field is required*... | มีคอลัมน์บังคับที่ยังว่าง | ตรวจว่าสูตร Patch เขียนค่าครบทุกคอลัมน์ที่ตั้ง Required |
| ...*The data source is not valid*... | ชื่อ data source ไม่ตรง | ตรวจชื่อใน Data แล้วแก้ในสูตร |

### 9.9 แอปช้า

1. ลดช่วงเวลาเป็น **รายสัปดาห์** หรือ **รายเดือน**
2. เลือกแผนกเดียวแทน **ทุกแผนก**
3. ตรวจว่า index ถูกสร้างครบ (ลิสต์ที่ไม่มี index จะช้ามากเมื่อข้อมูลเยอะ)
4. ปิด–เปิดแอปใหม่เพื่อล้าง cache โปรไฟล์
